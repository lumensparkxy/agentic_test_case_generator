# Documentation writing

Read the target text and only the sources needed to support the change. Infer
purpose, audience, tone, and format from the request and surrounding document.
For a typo, clarification, or bounded section update, edit directly without an
outline approval step. Ask only when missing intent materially changes the work;
reuse decisions and authorization already given.

For a substantial new document, choose the useful format: tutorial, how-to,
reference, or explanation. Use an outline to organize it when useful; request
outline approval only if the user asks for it or an unresolved decision requires
input. Do not expand an edit into all four documentation types.

Keep claims grounded in current source/configuration or relevant official
references. Preserve correct existing content, terminology, and links. Point to
a canonical command/policy guide instead of duplicating a changing checklist.
Validate changed links and examples; follow the documentation row of
[Testing Patterns](../../../docs/codebase/TESTING.md). Report the resulting change
and meaningful limitations concisely.
